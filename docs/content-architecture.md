# معماری محتوایی Parenting Course

## هدف

این سند قرارداد معماری محصول است. رابط فعلی فقط یک پوسته‌ی پروتوتایپ است؛ محتوای کامل باید بدون بازنویسی App Shell، ناوبری یا مدل پیشرفت به آن اضافه شود.

## اصل محوری

`والدگری و رابطه` هسته‌ی محصول است. والدگری دیجیتال یک لایه‌ی کاربردی روی مهارت‌های اصلی رابطه، مرزگذاری، تنظیم هیجان و اعتماد است؛ نه یک محصول جدا.

## لایه‌های محتوا

```text
Path
└── Module
    └── Lesson
        ├── Problem references
        ├── Solution references
        ├── Exercise
        ├── Checklist
        ├── Quiz
        └── Progress state
```

محتوای مکمل:

```text
Problem Library ──> Problem ──> Solution Page ──> Lesson / Exercise
Family Plan ──> Rules + routines + digital agreement + review cycle
Program ──> 7-day plan / 30-day plan ──> daily tasks ──> progress
```

## انواع محتوا

- **Path:** یک مسیر یادگیری بزرگ با هدف، مخاطب، ترتیب و ماژول‌ها.
- **Module:** یک بخش مفهومی درون مسیر؛ مثلاً «مرزگذاری و تعارض».
- **Lesson:** یک واحد قابل مطالعه یا اجرا.
- **Problem:** مسئله‌ای که والد در کتابخانه مشکل جست‌وجو می‌کند.
- **Solution Page:** پاسخ عملی و مستقل به یک Problem، با ارجاع به درس‌ها و تمرین‌ها.
- **Exercise:** فعالیت کوتاه، گفت‌وگو، مشاهده یا اقدام روزانه.
- **Checklist:** فهرست تعاملی با وضعیت هر مورد.
- **Quiz:** سؤال‌های ارزیابی/بازتابی، نه تشخیص پزشکی.
- **Program:** برنامه‌ی ۷روزه یا ۳۰روزه با taskهای روزانه.
- **Family Plan:** سند مشترک خانواده برای قوانین، زمان صفحه، خواب، مرور و توافق.

## ظرفیت محصول

مسیرهای نمایشی اولیه ممکن است محدود باشند، اما معماری باید این خانواده‌ها را پشتیبانی کند:

1. والدگری و رابطه
2. والدگری دیجیتال به‌عنوان لایه‌ی متصل به رابطه
3. مسیر کودک ۷ تا ۱۲ سال
4. برنامه خانواده و عادت‌های هفتگی
5. کتابخانه مشکل‌ها و راهکارها
6. زبان‌های جدید و حالت RTL/LTR

## وضعیت و انتشار

هر محتوای قابل انتشار باید از وضعیت‌های زیر عبور کند:

```text
draft -> review -> published -> archived
```

این وضعیت در مرحله‌ی فعلی فقط قراردادی است و هنوز CMS پیاده‌سازی نشده است.

## اصل توسعه

- محتوای ثابت نباید در renderer پخش شود.
- renderer باید با شناسه‌ها و داده‌های محتوا کار کند.
- شناسه‌ها و slugها پایدار بمانند.
- ترجمه از محتوا جدا باشد.
- پیشرفت با `contentId` و `itemId` ذخیره شود، نه با متن نمایشی.
